## 3. 一致性与安全门禁

| 项 | 状态 | 负责 issue |
| --- | --- | --- |
| Electron 与 Web 对同一夹具返回等价的核心 Client API / projection | pending | #116, #118 |
| Web 默认只绑定 loopback，拒绝缺失 / 无效认证 | pending | #118 |
| Web 拒绝 local-only / 破坏性命令，只允许显式分类的写入 | pending | #118 |
| token / secret 不出现在普通日志、status JSON、events、errors、截图或发布产物中；仅 `jea url` 可打印已认证 URL | pending | #118, #120 |
| Renderer 不能在 preload / bridge 之外直接访问 Node / Electron / runtime 文件 | pending | #115, #116 |
| CSP、same-origin / CORS、IPC / RPC allowlist、参数校验、脱敏测试通过 | pending | #116, #118 |
| 现有门禁不降级：`npm run check`、coverage、Desktop tests / typecheck / build / smoke、shared renderer / Web build / smoke、`npm run audit:ci`、CodeQL | pending | #122 |
| #77 已修复，或仍是精确、未过期、已文档化的 audit-baseline 例外；任何 mismatch 阻断发布 | pending | #77 |

`npm run audit:ci` 必须留在发布 / 认证路径中。不要复制或削弱 `scripts/ci-audit.mjs`。详见 [0.1.0-security-debt.md](./0.1.0-security-debt.md)。
