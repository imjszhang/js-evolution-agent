# 0.1.0 与 #77：发布阻断规则

跟踪 issue：[#77](https://github.com/imjszhang/js-evolution-agent/issues/77)  
供应链门禁：`npm run audit:ci` → `scripts/ci-audit.mjs`  
基线文件：[`.github/security/audit-baseline.json`](../../.github/security/audit-baseline.json)

## 规则

**在 #77 修复之前，或在它仍然是一条精确、未过期、已文档化的 audit-baseline 例外之前，不得发布 JEA 0.1.0。**

允许发布的唯一条件（二选一）：

1. `#77` 已关闭，且 `npm audit --omit=dev` 不再把相关 GHSA 报为 high/critical；基线中对应条目已删除。
2. 这些 GHSA **仍然精确匹配** `.github/security/audit-baseline.json` 中未过期、且 `fixAvailable=false` 的例外。任何 mismatch、过期、或上游已提供修复，都必须阻断发布。

| --- | --- | --- |
| GHSA-vrm6-8vpv-qv8q | undici | `@cursor/sdk > @connectrpc/connect-node > undici` |

| GHSA-vxpw-j846-p89q | undici | `@cursor/sdk > @connectrpc/connect-node > undici` |

不要把实时漏洞列表抄进 `SECURITY.md`。

## 认证路径

发布 / 认证路径必须继续调用现有门禁，而不是复制一份更弱的检查：

```bash
npm run audit:ci
```

Wave 1 额外检查（`scripts/release-audit-gate.mjs`）只验证：

- 根 `package.json` 的 `audit:ci` 仍指向 `scripts/ci-audit.mjs`
- `.github/workflows/release-macos.yml` 仍执行 `npm run audit:ci`
- 本文件与 [0.1.0-certification.md](./0.1.0-certification.md) 仍写明 #77 阻断规则
- 基线文件仍引用 #77

`jea audit queue` 是演化证据 / 决策队列检查，**不是** npm 供应链审计。
