- [ ] `npm run release:preflight -- --strict --json`：package、lockfile、资源、builder、产品身份与 ACP runtime 均为 `0.3.1`
- [ ] Protocol `jea.client` 保持 `1.0.0`（additive）；控制面 *contract* 版本保持 `0.3.0`，不另造第二套 contract version
- [ ] `npm run desktop:package` 产出 `JEA-0.3.1-macos-arm64.dmg`、`JEA-0.3.1-macos-arm64.zip` 与 `SHA256SUMS`
- [ ] stage 与最终产物扫描不含 `.env`、用户 runtime、开发者绝对路径或测试文件
- [ ] `build-metadata.json` 记录 `0.3.1`、完整 commit SHA、时间、platform/arch，并且 `dirty=false`
- [ ] package smoke、产品旅程、恢复矩阵、launch smoke、30 分钟 `soak-report.json` 与最终 `certification-evidence.json` 完整
- [ ] 30 分钟 packaged soak 必须在 certification evidence 生成前通过；soak 与 evidence 必须来自同一 clean build id / commit

## 发布门禁

- [ ] `npm run audit:ci` 保持在认证路径，#77 baseline 必须精确匹配且未过期
- [ ] `jea audit closure --json` 通过 `policies/release/closure-target-0.2.0.json`；`closure-audit.json` 必须进入同 build 的 certification evidence
- [ ] `control-plane-audit.json` 仍须进入同 build 的 certification evidence；`ok === true` 且 `gate.target_id === '0.3.0-reactor-control-plane'`
- [ ] dirty source tree 继续被打包 provenance / publish guard 拒绝
- [ ] publish guard 在缺失或不完整认证证据时 fail-closed
- [ ] Attach Release Assets 只接受既有 `v0.3.1` Release 与 allowlist 内资产（含 `soak-report.json`、`closure-audit.json`、`control-plane-audit.json` 和 `certification-evidence.json`）
- [ ] `run_id` 必须由 `gh api` 核实为 `.github/workflows/release-macos.yml` 的 successful run，且 `head_sha` 与目标 tag commit SHA 完全一致
- [ ] 下载后再次核实 `build-metadata.json` 为 full commit + `dirty=false`，package smoke 已通过、认证状态为 `certified`，并在 attach 前运行 publish guard
- [ ] 既有同名 Release asset 默认冲突失败；只有 dispatch 显式勾选 `replace_existing_assets` 才允许 `--clobber`
- [ ] 操作者明确放行后才可创建 tag / Release；工作流不得自行发布

## 明确不做

- Intel macOS、Windows 或 Linux 安装包
- notarization、公证或自动更新
- 自动触发发布；认证与附件工作流继续只允许 manual dispatch / 显式调用
- 放宽 clean-tree guard、#77 baseline 或 publish fail-closed 规则
- 改写冻结的 `0.2.0-belief-loop` closure target
- 改写冻结的 `0.3.0-reactor-control-plane` 目标，或另造 0.3.1 control-plane contract
- 纳入 Dependabot 生产依赖组（#235 / #244）或未进 main 的 web-host stale-bundle 修复
